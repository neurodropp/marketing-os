# F4.03 — Differentiation

Version: 0.3.0 · Owner: `positioning-agent` · Skill: `positioning`

## When to use

Use when the requested work concerns differentiation and needs the following output: Differentiation matrix: parity, difference, buyer relevance, proof, defensibility, imitation risk.

Read [the process execution contract](../processes.md#execution-contract) before starting. Use only the active brand workspace.

## Inputs and readiness

| ID | Required input to assess |
| --- | --- |
| i1 | Competitor comparison |
| i2 | product evidence |
| i3 | buyer selection criteria |

Bind each input to local evidence or a dated source. Missing data may support a clearly labeled draft or collection plan; it cannot support a verified result. Mark an irrelevant input not applicable with a specific reason.

## Procedure

1. **F4.03.a** — List category points of parity required to be considered.
2. **F4.03.b** — Identify differences that matter to the buyer and tie them to outcomes.
3. **F4.03.c** — Assess whether each advantage is demonstrable and sustainable.
4. **F4.03.d** — Build a comparison using equivalent criteria and dated evidence.
5. **F4.03.e** — Model how a competitor could imitate the claim and identify the underlying defense.

## Output contract

Differentiation matrix: parity, difference, buyer relevance, proof, defensibility, imitation risk.

Save the deliverable under `strategy/<run-id>/` in the active workspace. Choose Markdown for narrative work, CSV/XLSX for tabular calculations, and native media files where the task requires them. Include source references, assumptions, decision status and next owner. Never overwrite an accepted version.

## Quality gates

| ID | Acceptance criterion |
| --- | --- |
| q1 | No difference is called valuable without a buyer consequence. |
| q2 | Comparisons use equivalent offer conditions. |
| q3 | Superlatives have support or are removed. |

For each gate, record pass, fail or unverified with a local evidence file and an explanation. Inspect the actual output. A failed or unverified gate prevents ready/executed status; record a draft and a concrete remedy instead.

## Stop, recover and hand off

If no defensible distinction exists, recommend a validation or product change rather than fabricating uniqueness.

Record the blocker, affected scope, evidence needed and next owner. Preserve completed work. For a failed external action, inspect actual state before retrying; do not repeat a potentially duplicate send, payment or publication. Use at most the project revision budget, then return the unresolved decision.

Suggested downstream owner: `creative-strategy-agent`. If the requested scope continues into the next domain; otherwise return the accepted artifact to the orchestrator.

Propose only material new evidence, decisions or learning to the second brain. Do not silently accept strategy changes. Save a session checkpoint with artifact paths, process/run ID and remaining work.
