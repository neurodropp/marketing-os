# F3.07 — Brand equity and reputation

Version: 0.3.0 · Owner: `brand-strategy-agent` · Skill: `brand-strategy`

## When to use

Use when the requested work concerns brand equity and reputation and needs the following output: Brand-equity baseline and reputation risk register with metric definitions, samples, associations, trends and actions.

Read [the process execution contract](../processes.md#execution-contract) before starting. Use only the active brand workspace.

## Inputs and readiness

| ID | Required input to assess |
| --- | --- |
| i1 | Brand research |
| i2 | listening evidence |
| i3 | awareness or perception measures |

Bind each input to local evidence or a dated source. Missing data may support a clearly labeled draft or collection plan; it cannot support a verified result. Mark an irrelevant input not applicable with a specific reason.

## Procedure

1. **F3.07.a** — Define awareness and salience measures with population, category cue and measurement method.
2. **F3.07.b** — Map observed associations and their source strength.
3. **F3.07.c** — Identify trust drivers and breaches using attributable evidence.
4. **F3.07.d** — Compare perception over equivalent samples and time windows.
5. **F3.07.e** — Maintain reputation risks with likelihood, impact, response owner and leading signals.

## Output contract

Brand-equity baseline and reputation risk register with metric definitions, samples, associations, trends and actions.

Save the deliverable under `brand/<run-id>/` in the active workspace. Choose Markdown for narrative work, CSV/XLSX for tabular calculations, and native media files where the task requires them. Include source references, assumptions, decision status and next owner. Never overwrite an accepted version.

## Quality gates

| ID | Acceptance criterion |
| --- | --- |
| q1 | Awareness is not inferred from impressions alone. |
| q2 | Sentiment limitations and sample changes are disclosed. |
| q3 | Each material reputation risk has an escalation owner. |

For each gate, record pass, fail or unverified with a local evidence file and an explanation. Inspect the actual output. A failed or unverified gate prevents ready/executed status; record a draft and a concrete remedy instead.

## Stop, recover and hand off

Do not claim a change in brand equity from incomparable samples or isolated anecdotes.

Record the blocker, affected scope, evidence needed and next owner. Preserve completed work. For a failed external action, inspect actual state before retrying; do not repeat a potentially duplicate send, payment or publication. Use at most the project revision budget, then return the unresolved decision.

Suggested downstream owner: `creative-strategy-agent`. If the requested scope continues into the next domain; otherwise return the accepted artifact to the orchestrator.

Propose only material new evidence, decisions or learning to the second brain. Do not silently accept strategy changes. Save a session checkpoint with artifact paths, process/run ID and remaining work.
