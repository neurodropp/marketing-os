# O2.03 — Visual and multimedia production

Version: 0.3.0 · Owner: `content-production-agent` · Skill: `content-production`

## When to use

Use when the requested work concerns visual and multimedia production and needs the following output: Production package: source files, final renders, rights ledger, captions/transcripts, export specifications, QA notes.

Read [the process execution contract](../processes.md#execution-contract) before starting. Use only the active brand workspace.

## Inputs and readiness

| ID | Required input to assess |
| --- | --- |
| i1 | Creative brief |
| i2 | asset rights |
| i3 | target formats and production tools |

Bind each input to local evidence or a dated source. Missing data may support a clearly labeled draft or collection plan; it cannot support a verified result. Mark an irrelevant input not applicable with a specific reason.

## Procedure

1. **O2.03.a** — Translate the concept into layout, storyboard or shot requirements.
2. **O2.03.b** — Plan or produce photography with required permissions and subject treatment.
3. **O2.03.c** — Produce video with a clear sequence, pacing and caption needs.
4. **O2.03.d** — Specify or produce audio with intelligible speech and appropriate rights.
5. **O2.03.e** — Adapt motion and exports to target formats and inspect the resulting files.

## Output contract

Production package: source files, final renders, rights ledger, captions/transcripts, export specifications, QA notes.

Save the deliverable under `content/<run-id>/` in the active workspace. Choose Markdown for narrative work, CSV/XLSX for tabular calculations, and native media files where the task requires them. Include source references, assumptions, decision status and next owner. Never overwrite an accepted version.

## Quality gates

| ID | Acceptance criterion |
| --- | --- |
| q1 | Actual exported files are inspected where tools permit. |
| q2 | Rights and attribution requirements are recorded. |
| q3 | Critical text, audio and captions remain usable in target placements. |

For each gate, record pass, fail or unverified with a local evidence file and an explanation. Inspect the actual output. A failed or unverified gate prevents ready/executed status; record a draft and a concrete remedy instead.

## Stop, recover and hand off

If generation or rendering tools are absent, deliver a production-ready specification and mark media unproduced.

Record the blocker, affected scope, evidence needed and next owner. Preserve completed work. For a failed external action, inspect actual state before retrying; do not repeat a potentially duplicate send, payment or publication. Use at most the project revision budget, then return the unresolved decision.

Suggested downstream owner: `demand-generation-agent`. If the requested scope continues into the next domain; otherwise return the accepted artifact to the orchestrator.

Propose only material new evidence, decisions or learning to the second brain. Do not silently accept strategy changes. Save a session checkpoint with artifact paths, process/run ID and remaining work.
