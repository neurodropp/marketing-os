# O5.01 — Community management

Version: 0.3.0 · Owner: `community-management-agent` · Skill: `community-management`

## When to use

Use when the requested work concerns community management and needs the following output: Community operating kit: rules, response examples, activation plan, events, escalation matrix, moderation log.

Read [the process execution contract](../processes.md#execution-contract) before starting. Use only the active brand workspace.

## Inputs and readiness

| ID | Required input to assess |
| --- | --- |
| i1 | Community purpose |
| i2 | moderation rules |
| i3 | owner and escalation coverage |

Bind each input to local evidence or a dated source. Missing data may support a clearly labeled draft or collection plan; it cannot support a verified result. Mark an irrelevant input not applicable with a specific reason.

## Procedure

1. **O5.01.a** — Translate moderation rules into examples and proportionate actions.
2. **O5.01.b** — Draft responses that address the member's actual question and preserve boundaries.
3. **O5.01.c** — Design member activation around useful participation rather than engagement bait.
4. **O5.01.d** — Plan community events with facilitation, accessibility and follow-up.
5. **O5.01.e** — Define safety escalation, recordkeeping and review of moderation decisions.

## Output contract

Community operating kit: rules, response examples, activation plan, events, escalation matrix, moderation log.

Save the deliverable under `reports/<run-id>/` in the active workspace. Choose Markdown for narrative work, CSV/XLSX for tabular calculations, and native media files where the task requires them. Include source references, assumptions, decision status and next owner. Never overwrite an accepted version.

## Quality gates

| ID | Acceptance criterion |
| --- | --- |
| q1 | Rules apply consistently to comparable cases. |
| q2 | Moderation actions record rationale and scope. |
| q3 | Coverage and escalation ownership are real and current. |

For each gate, record pass, fail or unverified with a local evidence file and an explanation. Inspect the actual output. A failed or unverified gate prevents ready/executed status; record a draft and a concrete remedy instead.

## Stop, recover and hand off

Escalate threats or sensitive personal situations to the designated responsible service; do not improvise beyond authority.

Record the blocker, affected scope, evidence needed and next owner. Preserve completed work. For a failed external action, inspect actual state before retrying; do not repeat a potentially duplicate send, payment or publication. Use at most the project revision budget, then return the unresolved decision.

Suggested downstream owner: `customer-research-agent`. If the requested scope continues into the next domain; otherwise return the accepted artifact to the orchestrator.

Propose only material new evidence, decisions or learning to the second brain. Do not silently accept strategy changes. Save a session checkpoint with artifact paths, process/run ID and remaining work.
