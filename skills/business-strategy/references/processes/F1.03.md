# F1.03 — Unit economics

Version: 0.3.0 · Owner: `business-strategy-agent` · Skill: `business-strategy`

## When to use

Use when the requested work concerns unit economics and needs the following output: Unit-economics model: cohort, period, customer count, net revenue, variable cost, CAC, cumulative contribution, payback, assumptions.

Read [the process execution contract](../processes.md#execution-contract) before starting. Use only the active brand workspace.

## Inputs and readiness

| ID | Required input to assess |
| --- | --- |
| i1 | Revenue transactions by cohort |
| i2 | acquisition costs and allocation rules |
| i3 | variable delivery costs and retention history |

Bind each input to local evidence or a dated source. Missing data may support a clearly labeled draft or collection plan; it cannot support a verified result. Mark an irrelevant input not applicable with a specific reason.

## Procedure

1. **F1.03.a** — Calculate net revenue and contribution per acquired customer, treating refunds and taxes consistently.
2. **F1.03.b** — Divide allocated acquisition costs by newly acquired customers in the same scope and period.
3. **F1.03.c** — Estimate cumulative cohort contribution and distinguish observed value from extrapolated lifetime value.
4. **F1.03.d** — Compare cumulative contribution against acquisition cost to identify payback by offer and channel.
5. **F1.03.e** — Stress-test retention, gross margin and acquisition cost, then propose viability thresholds.

## Output contract

Unit-economics model: cohort, period, customer count, net revenue, variable cost, CAC, cumulative contribution, payback, assumptions.

Save the deliverable under `strategy/<run-id>/` in the active workspace. Choose Markdown for narrative work, CSV/XLSX for tabular calculations, and native media files where the task requires them. Include source references, assumptions, decision status and next owner. Never overwrite an accepted version.

| ID | Acceptance criterion |
| --- | --- |

For each gate, record pass, fail or unverified with a local evidence file and an explanation. Inspect the actual output. A failed or unverified gate prevents ready/executed status; record a draft and a concrete remedy instead.

Record the blocker, affected scope, evidence needed and next owner. Preserve completed work. For a failed external action, inspect actual state before retrying; do not repeat a potentially duplicate send, payment or publication.
