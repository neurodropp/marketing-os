# O6.01 — Marketing onboarding

Version: 0.3.0 · Owner: `lifecycle-marketing-agent` · Skill: `lifecycle-marketing`

## When to use

Use when the requested work concerns marketing onboarding and needs the following output: Onboarding program: trigger, expectation, first task, education, activation event, risk signal, support route.

Read [the process execution contract](../processes.md#execution-contract) before starting. Use only the active brand workspace.

## Inputs and readiness

| ID | Required input to assess |
| --- | --- |
| i1 | Purchase context |
| i2 | product value milestones |
| i3 | service capacity |

Bind each input to local evidence or a dated source. Missing data may support a clearly labeled draft or collection plan; it cannot support a verified result. Mark an irrelevant input not applicable with a specific reason.

## Procedure

1. **O6.01.a** — Prepare a welcome that confirms purchase, access and immediate next steps.
2. **O6.01.b** — Set realistic expectations for timing, support and effort.
3. **O6.01.c** — Provide initial education focused on the first useful task.
4. **O6.01.d** — Guide the customer toward an observable activation milestone.
5. **O6.01.e** — Identify stalled progress and route appropriate help.

## Output contract

Onboarding program: trigger, expectation, first task, education, activation event, risk signal, support route.

Save the deliverable under `campaigns/<run-id>/` in the active workspace. Choose Markdown for narrative work, CSV/XLSX for tabular calculations, and native media files where the task requires them. Include source references, assumptions, decision status and next owner. Never overwrite an accepted version.

## Quality gates

| ID | Acceptance criterion |
| --- | --- |
| q1 | The welcome agrees with actual purchased terms. |
| q2 | Activation measures value received. |
| q3 | Stalled users have a support path rather than repetitive reminders. |

For each gate, record pass, fail or unverified with a local evidence file and an explanation. Inspect the actual output. A failed or unverified gate prevents ready/executed status; record a draft and a concrete remedy instead.

## Stop, recover and hand off

Do not report activation from message opens or account creation alone.

Record the blocker, affected scope, evidence needed and next owner. Preserve completed work. For a failed external action, inspect actual state before retrying; do not repeat a potentially duplicate send, payment or publication. Use at most the project revision budget, then return the unresolved decision.

Suggested downstream owner: `performance-analysis-agent`. If the requested scope continues into the next domain; otherwise return the accepted artifact to the orchestrator.

Propose only material new evidence, decisions or learning to the second brain. Do not silently accept strategy changes. Save a session checkpoint with artifact paths, process/run ID and remaining work.
