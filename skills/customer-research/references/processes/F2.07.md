# F2.07 — Insight management

Version: 0.3.0 · Owner: `customer-research-agent` · Skill: `customer-research`

## When to use

Use when the requested work concerns insight management and needs the following output: Insight register: source IDs, claim type, evidence strength, contradiction, opportunity, hypothesis, owner, review date.

Read [the process execution contract](../processes.md#execution-contract) before starting. Use only the active brand workspace.

## Inputs and readiness

| ID | Required input to assess |
| --- | --- |
| i1 | Research artifacts |
| i2 | existing insight records |
| i3 | pending decisions |

Bind each input to local evidence or a dated source. Missing data may support a clearly labeled draft or collection plan; it cannot support a verified result. Mark an irrelevant input not applicable with a specific reason.

## Procedure

1. **F2.07.a** — Index source files with stable IDs, dates, method and access scope.
2. **F2.07.b** — Tag each claim as observation, interpretation or assumption and assess evidence limitations.
3. **F2.07.c** — Cluster recurring and contradictory signals into decision-relevant opportunities.
4. **F2.07.d** — Convert uncertain implications into falsifiable hypotheses with a proposed validation method.
5. **F2.07.e** — Propose versioned customer-model updates, identifying which prior beliefs would change.

## Output contract

Insight register: source IDs, claim type, evidence strength, contradiction, opportunity, hypothesis, owner, review date.

Save the deliverable under `research/<run-id>/` in the active workspace. Choose Markdown for narrative work, CSV/XLSX for tabular calculations, and native media files where the task requires them. Include source references, assumptions, decision status and next owner. Never overwrite an accepted version.

## Quality gates

| ID | Acceptance criterion |
| --- | --- |
| q1 | Every insight can be traced to source material. |
| q2 | Contradictions remain visible rather than averaged away. |
| q3 | Updates distinguish new evidence from approved strategic decisions. |

For each gate, record pass, fail or unverified with a local evidence file and an explanation. Inspect the actual output. A failed or unverified gate prevents ready/executed status; record a draft and a concrete remedy instead.

## Stop, recover and hand off

Do not overwrite an approved customer model when the evidence only supports a proposal.

Record the blocker, affected scope, evidence needed and next owner. Preserve completed work. For a failed external action, inspect actual state before retrying; do not repeat a potentially duplicate send, payment or publication. Use at most the project revision budget, then return the unresolved decision.

Suggested downstream owner: `positioning-agent`. If the requested scope continues into the next domain; otherwise return the accepted artifact to the orchestrator.

Propose only material new evidence, decisions or learning to the second brain. Do not silently accept strategy changes. Save a session checkpoint with artifact paths, process/run ID and remaining work.
